## 1. Архитектура

Все сервисы Puls живут в **изолированной overlay-сети** `puls-network`.
К ней подключаются только сервисы проекта + `dokploy-traefik` (входной прокси 80/443).

```
Интернет
   │
dokploy-traefik  (80/443, TLS)
   │
puls-network (overlay, attachable)  ← изолирована от mypay/digitalitem/other-*
   ├── puls-data   (MySQL 8, сервис puls-data-uuk1lw)
   ├── puls-backend (NestJS, сервис puls-backend-2tzxel)
   ├── puls-frontend (nginx, сервис puls-frontend-dttzlw)
   └── puls-minio   (MinIO, контейнер puls-minio-iyq5wb-minio-1)
```

### Чистые DNS-алиасы внутри сети

| Алиас | Реальный объект | Примечание |
|---|---|---|
| `puls-data` | swarm-сервис `puls-data-uuk1lw` | MySQL |
| `backend` | swarm-сервис `puls-backend-2tzxel` | API |
| `frontend` | swarm-сервис `puls-frontend-dttzlw` | nginx |
| `minio` | контейнер `puls-minio-iyq5wb-minio-1` | MinIO |

> Алиасы задаются вручную и **слетают после каждого редеплоя** в Dokploy.
> После любого деплоя запускайте скрипт из раздела 4.

## 3. Порядок деплоя

1. Закоммитить изменения в репозиториях (`front-puls`, `backend-nest`)
2. В Dokploy пересобрать нужные сервисы (backend → frontend)
3. **Запустить скрипт восстановления алиасов** (раздел 4)
4. Проверить:
   - `curl https://puls.app.sellixcore.ru/api/company/info` → 200
   - `curl https://puls.app.sellixcore.ru/uploads/71/bGv09vhfBzgLWaRUJMWc2xDuPr0V.jpg` → 200
   - картинка отдаётся (не пустая)

## 4. Восстановление сети и алиасов

Файл: `front/scripts/fix-dns-alias.ps1` (запускать с хоста, где настроен WSL Ubuntu):

```powershell
powershell -ExecutionPolicy Bypass -File front/scripts/fix-dns-alias.ps1
```

Скрипт:
1. создаёт сеть `puls-network` (overlay, attachable), если её нет
2. подключает контейнер MinIO с алиасами `minio`, `puls-minio`
3. подключает `dokploy-traefik`
4. вешает алиасы `puls-data` / `backend` / `frontend` на swarm-сервисы

## 5. Решение типовых проблем

### 5.1. Сайт/панель полностью недоступны (`cluster`, `puls`, всё)
**Симптом:** `curl https://...` → `exit 7`, ничего не открывается.
**Причина:** контейнер `dokploy-traefik` упал (`Exited 128`) — он обслуживает все домены на 80/443. Частая причина падения — мёртвая нода swarm: overlay-сети виснут, `docker start` даёт `context deadline exceeded`.
**Решение:**
```bash
docker node ls                          # ищем ноду Down
docker node rm --force <ID-down-ноды>   # удаляем
# переподключить сети traefik:
docker network disconnect dokploy-network dokploy-traefik 2>/dev/null
docker network connect dokploy-network dokploy-traefik
docker start dokploy-traefik
```
Если всё ещё не стартует — перезапустить dockerd:
```bash
systemctl restart docker
```

### 5.2. Backend: `getaddrinfo ENOTFOUND puls-data`
**Причина:** короткое имя сервиса не резолвится в overlay — нужен полный (`puls-data-uuk1lw`) или алиас `puls-data` на `puls-network`.
**Решение:** после деплоя запустить `fix-dns-alias.ps1` (раздел 4) и убедиться, что в Dokploy UI у backend `DB_HOST=puls-data`.

### 5.3. Backend: `getaddrinfo ENOTFOUND puls-minio-iyq5wb`
**Причина:** `puls-minio-iyq5wb` — это имя **сети**, а контейнер называется `puls-minio-iyq5wb-minio-1`. Также сам MinIO мог упасть.
**Решение:**
```bash
docker ps --filter "name=puls-minio"    # жив ли контейнер
docker start puls-minio-iyq5wb-minio-1  # если упал
# в Dokploy UI у backend: MINIO_ENDPOINT=minio (алиас на puls-network)
```

### 5.4. `Unknown column 'properties'` в логах backend
**Причина:** сервер обращался не к той базе из-за неверного `DB_HOST` (резолвился другой MySQL).
**Решение:** исправить `DB_HOST=puls-data` (раздел 2). Схема `properties` / `excluded_properties` в `puls-data` существует.

### 5.5. `401 Invalid credentials` при входе в админку
**Причина:** неверные логин/пароль менеджера.
**Решение:** сверить учётные данные в БД:
```bash
docker exec puls-data-uuk1lw.1.<task-id> mysql -upulsar -ppulsar pulsar -e "SELECT id, email FROM manager;"
```
или сбросить пароль (bcrypt) через backend.

### 5.6. Медленная загрузка сайта / картинок
- первый запрос к картинке идёт через sharp-сжатие (~2.5 с), дальше отдаётся из nginx-кэша (30 дней) — повторные запросы ~0.4 с
- проверить кэш: заголовок `X-Cache-Status: HIT`
- кэш очищается: `rm -rf /var/cache/nginx/uploads/*` внутри контейнера frontend + reload

### 5.7. После рестарта сервера всё упало
**Порядок подъёма:** `dockerd` поднимает swarm-сервисы сам; контейнеры `dokploy-traefik` и `puls-minio-iyq5wb-minio-1` (restart: unless-stopped) должны подняться автоматически. Проверить:
```bash
docker ps --format "{{.Names}} {{.Status}}" | grep -iE "puls|traefik"
```

## 6. Полезные команды

```bash
# статус сервисов
docker service ls | grep puls

# резолвинг изнутри backend
BACKEND=$(docker ps -q --filter "name=puls-backend" | head -1)

# логи backend
docker logs --tail 50 $(docker ps -q --filter "name=puls-backend" | head -1)

# что в сети puls-network
docker network inspect puls-network --format '{{range .Containers}}{{.Name}} {{end}}'
```
